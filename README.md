# 白名单群持续聊天上下文

本插件由 Sirin 发起并维护，使用 OpenAI Codex 协助开发与迭代。

本插件会持续接收并持久化白名单群内所有成员的消息，包括没有 `@` 机器人的消息。白名单群每次正常调用 LLM 时，插件都会自动把最近一段群聊作为滑动窗口临时加入当前请求，不要求用户先说“阅读聊天记录”。插件只提供上下文，不会因为普通群消息而主动回复。

## 开始监听特定群

安装并启用插件后，由 AstrBot 管理员在目标群发送：

- `/historywatch add`：从此刻开始持续监听，并为当前群开启每轮自动上下文。
- `/historywatch status`：查看当前群是否正在监听，以及最近 24 小时保存数量。
- `/historywatch remove`：停止监听当前群；已经保存的历史不会自动删除。

也可以在插件配置的“持续监听的群聊白名单”中填写群 ID、完整 UMO，或
`平台:群ID`，每行或逗号分隔。为了避免误收集，默认不会监听任何群；“监听全部群聊”默认关闭。

监听从加入白名单之后开始，插件无法补回安装前或未监听期间的历史。平台适配器也必须实际向
AstrBot 下发未 `@` 机器人的群消息；如果协议端本身过滤了这些消息，插件无法在应用层恢复。

## 每轮自动上下文

默认每轮带入最近 2 小时、最多 100 条且不超过 20000 字符的群消息。以下设置可以分别调整：

- `continuous_context_enabled`：是否为白名单群每轮自动注入。
- `continuous_context_hours`：滑动窗口回溯小时数。
- `continuous_max_messages`：每轮自动上下文最多消息数。
- `continuous_max_chars`：每轮自动上下文字符上限。

当前触发模型的那条用户消息会从历史块中排除，因为它已经存在于本轮正常输入中。上下文使用
AstrBot 临时消息标记，只参与当前一轮，不会把整段原始聊天记录写回普通会话历史。

用户仍可明确要求更大的时间范围，例如：

- `看看最近 30 分钟的聊天记录`
- `总结一下大家过去两小时聊了什么`
- `读一下今天的群消息`
- `回顾昨天/昨晚/本周的聊天`
- `看看所有可用的聊天记录`

明确读取但未指定范围时使用配置中的 `default_hours`（默认 6 小时），并使用较大的显式读取上限。记录默认保留 14 天；发生截断时会在注入内容中明确标注。

## 安全行为

历史消息会被标记为“聊天数据而非系统指令”，并进行 XML 字符转义。模型可以据此理解群聊内容，但不应执行历史消息中试图改变规则、泄露信息或调用工具的指令。

持续记录群聊可能涉及隐私与合规要求。请只添加已取得适当授权、群成员知情的群聊，并妥善保护 AstrBot 数据目录；插件不会把数据库内容主动上传到其他服务，但白名单群每次调用模型时，滑动窗口内的历史都会发送给当前配置的模型提供商。

每条历史消息都会同时标注昵称和稳定用户 ID。注入时，插件会向系统提示词加入身份识别规则：不同 ID 即使同名也必须视为不同用户；同一 ID 即使改名仍视为同一用户；涉及“我”时按当前请求者 ID 匹配。

## 数据

SQLite 数据库位于 AstrBot 的插件数据目录：

`data/plugin_data/astrbot_plugin_chat_history_context/history.sqlite3`

卸载插件前如需保留聊天记录，请先备份该文件。
